## Why

Photos generated by this tool have to be manually pasted, one per page, into third-party photobook software (the various printing services' own tools). That software renders its own page background, and today's PNG/JPG output also paints an opaque background fill behind each photo. Where the two backgrounds are meant to match (e.g. both "black"), sub-pixel differences between the tool's fill color and the printing service's rendering show up as a visible seam around every pasted photo. Generating PNGs with a genuinely transparent background - not just a matching color - removes that seam by letting the printing service's own page background show through everywhere except the actual photo/text/border pixels.

## What Changes

- Add an `output.transparent` boolean config field (default `false`). When `true`, PNG page images are rendered with a real alpha channel instead of an opaque background fill: page margins, inter-photo gaps, and any letterboxing around a photo whose aspect ratio doesn't match its cell are left fully transparent (alpha=0), while photo, text, and border pixels stay fully opaque.
- Validate `output.transparent: true` at config-load time against `output.format`: only `png` supports it (`jpg` has no alpha channel; the PDF assembly workflow is out of scope for this change). Setting it with any other format is a configuration error, consistent with the existing format validation.
- Rework the two theme effects that currently rely on the page being fully opaque so they composite correctly on a transparent canvas too, rather than silently corrupting pixels or being disabled:
  - The drop shadow (`theme.borders.shadow`) already builds its soft edge on an isolated layer and alpha-composites it in; it currently discards that alpha by flattening to RGB before returning. It keeps its alpha through to final output.
  - The semi-transparent text-background box (`theme.text.text_background_enabled` / `theme.title.text_background_enabled`) and the text glyphs drawn on top of it currently use a paste-based shortcut that only produces correct color and alpha when painted over a fully opaque backdrop. Both are rewritten to composite correctly regardless of what's underneath, so they render correctly for both transparent and opaque output.
- No changes to PDF or JPG output behavior when `output.transparent` is left at its default.

## Capabilities

### New Capabilities

(none)

### Modified Capabilities

- `output-generation`: adds a transparent-background PNG output mode (new requirement + scenarios), the config validation rule tying it to `format: png`, and corrects the drop-shadow and text-background-box rendering requirements so they specify alpha-correct compositing rather than being silent about it.

## Impact

- `src/photobook_as_code/config.py`: new `OutputConfig.transparent` field and validation against `output.format`.
- `src/photobook_as_code/renderer.py`: `create_blank_page`, `draw_shadow`, `_draw_text_background`, and the text-glyph drawing path change to support and correctly composite onto a transparent RGBA canvas; `render_page`/`render_all_pages` thread the `transparent` flag through.
- `src/photobook_as_code/output.py`: `generate_png_pages` (and `generate_output`'s dispatch) preserve the alpha channel already present on RGBA page images when saving PNGs; no change needed for JPG/PDF paths since they never receive RGBA pages.
- `src/photobook_as_code/cli.py`: pass `pb_config.output.transparent` through to the renderer.
- Shipped themes (`classic.yaml` has `shadow: true`; `clean.yaml`/`clean2.yaml` have `text_background_enabled: true`) are exercised by the compositing fix and should be spot-checked visually after the change, both with and without `output.transparent`.
